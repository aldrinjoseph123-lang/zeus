# Zeus — pre-production audit, August 2026

A simulated working week at Protect24x7, run against an isolated `zeus_audit` database
built from empty. A rep chasing an enquiry, a manager clearing approvals, finance issuing
invoices — with the database checked after every step.

**Result:** 9 findings, 8 fixed. Two would have corrupted money data from day one, and
neither was visible to the test suite as it stood.

Published report with diagrams: https://claude.ai/code/artifact/e8acb661-ab91-417c-a78b-46dd8d132f8f

## Verified working

Migrations from empty with no drift · every document recomputed from its own lines to the
fil · payments and credit notes reconcile · reference numbers unique · all three approval
gates including self-approval refusal · issued documents locked · duplicate detection ·
lead conversion carrying history · 90-day registrations · renewals sweep · undo with
double-undo refusal · RBAC across four roles with no cost leakage · all 16 reports and
their Excel/PDF exports · all nine scheduler jobs.

## Method and its limits

`npm run db:simulate` creates the company history and refuses to run against any database
not named `zeus_audit`. Everything after that was done through the UI in role.

The browser automation could not reliably deliver mouse clicks into modal dialogs; where
that blocked progress the form was driven through the same React handlers a click fires
and the outcome verified in the database. Sign-in was not driven through the login form —
sessions were minted directly — so the form remains covered by its integration test rather
than by this audit.

Dev database untouched: 297 rows before, 297 after.
